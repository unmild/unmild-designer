Why Unmild Designer exists

Unmild Designer is built for the complete electronics workflow: shape the physical board, create the firmware, program the microcontroller, see the behavior, verify the design, and prepare it for manufacture.

The PCB canvas is built for direct work: place components, route traces, shape the board outline, use grid snapping and live coordinates, and adapt the interface with custom navigation, colors, shortcut keys, and dockable or floating panels.

Mool makes embedded development part of the same project. Select the microcontroller on the board, write C or C++, build through the compiler installed on your computer, generate the required target image, and program the device without leaving Unmild Designer.

Run makes the result visible: board behavior, component state, readings, pin activity, and issues remain beside the PCB. 3D review gives the physical design another perspective, while Simulation, Analysis, and Verification add circuit calculation, impedance estimates, ERC, and DRC to the engineering loop.

When the design is ready, one release workflow gathers manufacturing artwork, drill data, bill of materials, placement and stackup information, review documentation, and fabrication information into a professional delivery package.

Named in Sanskrit, on purpose

A few of Unmild Designer's own tools and file formats borrow their names from Sanskrit rather than the usual EDA-software vocabulary.

.tamas
darkness / dark energy

The project file extension. Every board is saved as a single .tamas file inside its project folder.

Mool
origin / source

The embedded firmware environment: write C/C++, build the selected target, program the microcontroller, and observe behavior beside the PCB.

Setu
bridge / connector

The wire tool — the thing that bridges one pad to another with a copper trace.

Saad
to call / to summon

The parts picker, also labeled Summon in the toolbox — call up a component and drop it on the board.
